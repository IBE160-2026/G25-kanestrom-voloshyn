# Epic 2 Context: Projects and study material

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Give the student a place for each course and get their material into it. A student can create, open, and rename Projects, accept a one-time privacy notice, upload documents and photos (with clear accept, warn, or reject outcomes and server-enforced limits), have the Project name itself from its first file, see and edit the Topics detected in each file, remove files, and find everything as they left it on return. Epic 2 also builds the shared machinery every later epic relies on: the Project read-only guard, the LLM gateway with deterministic mock mode, the extraction pipeline that turns any file into Sections, the in-process job runner (first used for `material_processing`), the usage quota service, and the Project home layout that later feature stories fill. FR-4 and FR-6 are Core and never cut; FR-7 (images, Story 2.5) is the second Extension to cut if time runs out, and cutting it also removes image uploads and the image limit.

## Stories

- Story 2.1: Create, open, and rename Projects
- Story 2.2: Upload documents and watch them get processed
- Story 2.3: See the privacy notice before my first upload
- Story 2.4: My Project names itself from its first file
- Story 2.5: Upload photos of my notes
- Story 2.6: See and edit the Topics in each file
- Story 2.7: Remove a file

## Requirements & Constraints

- **Projects:** a new Project has no name (placeholder "New project") until its first Material is Ready, then gets a content-derived name once, never a static "Project 1". Rename works any time on an active Project: trimmed, blank refused (`invalid_name`), capped at 100 characters, persists. Login lands on the most recently used active Project, or the empty Projects page. Another Account's Project id returns `not_found`.
- **Upload:** PDF, .docx, .pptx, .txt, .md, .jpg/.jpeg, .png, .heic only; one file per request, several in sequence; ≤ 50 MB each; ≤ 10 Materials per Project, where processing counts and rejected doesn't, and a processing file that ends rejected frees its slot. Each rule has its own message. The server enforces every limit whatever the client showed; two parallel uploads at 9 of 10 must not both succeed (automated test).
- **Integrity outcomes:** every format ends Ready, Ready-partly-unreadable (warning stored and shown, with named pages where relevant), or Rejected (reason shown). Thresholds are config defaults: paged files (PDF, .pptx) accept ≥ 80 % readable pages, warn 30–80 %, reject < 30 % or < 200 chars total; non-paged (.docx, .txt, .md) accept ≥ 1,000 chars, warn 200–999, reject < 200; a single image follows the gateway's `readable`/`partial`/`unreadable` verdict, rejecting under 50 chars. A readable page has ≥ 20 chars. Scanned PDF pages without a text layer are unreadable (no OCR of PDFs). Corrupt, encrypted, or mismatched files are rejected.
- **Images (FR-7):** printed or handwritten text is extracted; afterwards no feature treats an image Material differently. 25 images per Account per day (Europe/Oslo calendar day); the 26th is declined with a clear message; "{n} images left today" shows at ≤ 10 left.
- **Privacy notice:** before the Account's first upload (button or drop; the phone entry gets the same gate in Epic 6), nothing uploads until accepted; Cancel discards dropped files; acceptance is saved to the Account and never blocks again; the text stays reachable. The server refuses uploads without acceptance (`privacy_notice_required`). Wording claims only that files go to an external AI service through OpenRouter, are used only for the student's own material, aren't shared, and aren't kept by the provider.
- **Topics:** detected only after extraction succeeds; target `clamp(ceil(pages/5), 3, 100)`, where a page is a PDF page, slide, or photo, or ~500 words for .docx/.txt/.md; computed and enforced by the server only. Every Section is covered; above 100, content is grouped under broader Topics, never dropped. Students can rename, merge (same file only), delete (never the last), and add (refused past 100); edits stay within their Material and persist. A student-added Topic absent from the material must never produce fabricated content later.
- **Removal:** any Material in an active Project, including Reading… and Rejected ones. Ready needs confirmation; Rejected is immediate. Removing a Reading… file cancels its processing. The slot frees at once; generated content stays; a failed removal changes nothing and is reported.
- **Resume:** reopening a Project shows every non-removed file with its Topics as left.
- **Data use and logging:** never log Study Material text, tokens, or keys. Material is used only for its owner and never shared across Accounts.

## Technical Decisions

- **Projects (`services/projects`):** `projects` with `name`, `name_source` (NULL / `auto` / `student`), `archived_at`, `deleted_at`, cascading from `profiles`. `projects.require_active` raises `409 project_read_only` and is called first by every content mutation (upload, removal, Topic edits, rename, later generation). A route test asserts every mutating route calls it or is on the bookkeeping allowlist (prefs, job seen/cancel, and the others named in the spine). Auto-naming runs after the Material's ready commit via `projects.auto_name_if_unnamed` → `llm.name_project`, writing `UPDATE … WHERE name_source IS NULL`; failure leaves NULL and retries after the next ready file, never failing processing. `profiles.last_project_id` and `ui_prefs` (sidebar and per-Project Files panel collapse) already exist on `profiles`; write prefs via `PATCH /api/me/prefs`.
- **Scoping:** every repository function touching Project data takes `account_id`; any client-sent id (Material, Topic, Job) is checked against the URL's Project. No unscoped lookups.
- **Upload pipeline (`services/materials`, only writer of `study_materials.status`):** (1) validate type and size synchronously, and for an image reserve one quota unit; (2) store the original in the private `study-materials` bucket at `{account_id}/{project_id}/{material_id}/…` via `storage.py`; (3) one transaction: lock the Project row `FOR UPDATE`, re-check slots, insert with `status=processing` (on failure delete the original and release the unit); (4) enqueue `material_processing`, return `202`. One slot predicate everywhere: `removed_at IS NULL AND status IN ('processing','ready')`.
- **Extraction (`extraction/`):** PDF with pdfplumber, one Section per page; .pptx with MarkItDown split on its slide markers; .docx/.md split at headings then packed to ~500 words; .txt ~500-word chunks; images normalized to JPEG (pillow-heif for HEIC) then `extract_image_text`. Sections store `material_id`, `position`, `label` ("Page 4", "Slide 7: Mitosis"), Markdown text, and a `tsvector` with the `simple` config. Nothing reads originals after processing. Blocking parsers run only via `asyncio.to_thread`; integrity rules and Topic counts are pure sync helpers.
- **Processing job:** extract → integrity → Topics, then save Sections, Topics, and `ready`/`rejected` in one transaction under a lock on the Material row; save nothing if the Material was removed meanwhile. `materials.on_terminal` maps a failed, interrupted, or cancelled job to `rejected` (`processing_failed` / `interrupted`), freeing the slot and deleting the original after commit. Rejected rows keep file name and reason, not the original.
- **Jobs (`services/jobs`, sole writer of `generation_jobs`):** columns `id, account_id, project_id, kind, params, status, progress_step, cancel_requested, result_ref, error_code, created_at, finished_at, seen_at`. Handlers return a save plan; the runner applies it in a save transaction that locks the job row and aborts on `cancel_requested`, deleted Project, or removed Material. Asyncio tasks in-process, `JOBS_MAX_CONCURRENT=3`, task references kept. Startup sweep marks queued/running jobs `failed` (`interrupted`) and routes `material_processing` through `on_terminal`. `GET /api/projects/{id}/jobs` returns active plus finished-unseen jobs; the SPA polls every 2 s only while something is active and refetches on terminal transitions. No Redis, Celery, workers, or cron.
- **Transactions:** one pooled connection and transaction per request; services take `conn` and never commit. Job steps: read transaction → LLM/extraction call with no connection held → save transaction. No LLM call inside an open write; quota `reserve` is the only write allowed before one. Storage objects are deleted only after the DB change commits.
- **LLM gateway (`backend/app/llm/`, introduced in Story 2.4):** the only `openai` importer; `AsyncOpenAI` at OpenRouter with `LLM_TIMEOUT_SECONDS`; every live request sends `provider: {require_parameters: true, data_collection: "deny", zdr: true}` and `response_format: json_schema` with one schema retry, then `LLMOutputError`. Typed tasks returning Pydantic models from `llm/schemas.py`; this epic uses `name_project`, `extract_image_text`, `detect_topics`. Sections are labelled `S1…Sn` locally and mapped back to ids. Provider errors map to `llm_unavailable` (429 → rate limited, 402/403 → unavailable). Model ids from `LLM_TEXT_MODEL` / `LLM_VISION_MODEL`; prompts in `llm/prompts/`; only the gateway estimates tokens. Log task, model, duration, outcome.
- **Mock mode:** deterministic fixtures in `llm/fixtures/` parsed through the same schemas; `detect_topics` derives Topics from Section count; `extract_image_text` returns `partial` / `unreadable` for file names containing `-partial.` / `-unreadable.`, otherwise `readable`; `LLM_MOCK_DELAY_MS` delays tasks. Quotas still apply in mock mode. Tests always run `LLM_MODE=mock`.
- **Quotas (`services/usage`, only toucher of `usage_counters`):** keyed by `(account_id, usage_day, kind)`; `reserve` is one atomic upsert incrementing only `WHERE count < limit`, else `QuotaExceeded`; `remaining`; `release(kind, usage_day)` only after a provider error or when the vision call never happens (removed or cancelled before extraction). `image_extraction` limit 25; Topic detection and naming are unmetered.
- **Topics (`services/topics`):** `topics(id, material_id, label, group_label, position, origin auto|student)` and `topic_sections(topic_id, section_id)`. One `detect_topics` call per Material, chunked and merged above the context budget; a single-Section Material still gets ≥ 3 Topics (may share the Section). Merge unions Sections onto the first Topic's id; cross-Material merge → `422 topic_merge_cross_material`; `topic_last_cannot_delete`; `topic_limit_reached`. All edits require an active Project.
- **Removal tombstone:** one transaction sets `removed_at`, empties every Section's text and `tsvector` (keeping file name and labels), calls `jobs.cancel_for_material`, and applies the Mistake choice (wired in Story 3.3); original deleted after commit; unused image unit released. Removed Materials never appear in counts, scopes, capacity, or chat.
- **Mutability:** only the listed mutable columns change (`projects`: name, name_source, archived_at, deleted_at; `study_materials`: status, reject_reason, warning, warning_pages, removed_at; `sections`: text/tsvector once on removal; `topics`: label, position, group_label). Row deletes only via Topic delete/merge and the closed list in the spine.
- **Schema:** only SQL in `supabase/migrations/`, including the bucket and its policies; every table cascades from `projects` or `profiles`; UUID keys, `timestamptz`.
- **Errors used:** `not_found`, `invalid_name`, `project_read_only`, `unsupported_file_type`, `file_too_large`, `material_limit_reached`, `quota_exceeded`, `privacy_notice_required`, `topic_last_cannot_delete`, `topic_limit_reached`, `topic_merge_cross_material`, `interrupted`, `llm_unavailable`, `llm_output_invalid`, in the `{"error": {code, params, message}}` envelope.

## UX & Interaction Patterns

- **Shell:** Sidebar lists active Projects, "+ New project", per-Project "···" menu (Rename here; Archive/Delete arrive in Epic 7), "Hide projects" collapsing to the Sidebar strip; collapse saved to the Account; below 1024 px it starts collapsed. Inline rename in Sidebar row and Top bar: Enter saves, Esc cancels. Project home: chat column (Upload drop zone "Upload your notes to start" · "Upload from phone" while no file is Ready), empty tool buttons row, Files panel on the right. Composition from `mockups/key-project-home.html`; DESIGN.md wins.
- **Files panel:** header "Files · n of 10"; collapses to the Files strip ("n of 10", warning icon when any file is partly unreadable or rejected); collapse saved per Project, forced collapsed below 1024 px. Upload button and drag and drop on the panel. File row with status (Reading… with pulsing dot, static under reduced motion · Ready · Ready, partly unreadable with muted note · Rejected in error colour with reason) and "{n} topics". Updates live, no refresh. Muted "How your files are used" link.
- **Privacy notice:** calm modal, no error colour or icon: "Before your first upload", body text, "Cancel" · "Got it, upload"; continues the action that opened it (picker or dropped files). Reopened from the link with only "Close".
- **Topic list:** chips per file; click to rename (Enter saves), × deletes (no × on the last), "+ Add topic", multi-select (Ctrl+click or Space) then "Merge" which opens the merged Topic for rename. Chapter groups, collapsed above ~20, scrollable; Tab reaches each group row and chip, Enter/Space toggles a group. "Large file, some topics are grouped." at the ceiling. Failed edits show the Inline error and leave Topics unchanged.
- **Remove file:** row "···" → Remove opens the Remove file dialog ("Remove {file name}?", focus on Cancel, final "Remove" is the danger button; short variant for Reading… files: "Reading stops and the file won't be added."). Buttons disable while removing; failure keeps the dialog open with the Inline error. Rejected rows have no menu and remove at once. The mistakes checkbox stays hidden until Story 3.3.
- **Copy:** every string and error comes from EXPERIENCE.md's strings table into `en.json`/`nb.json` with plural forms; the Norwegian there was signed off on 2026-11-16 and is binding. Limit messages name the rule (supported types list, "This file is over 50 MB.", "A project can hold 10 files. Remove one to add another.", "You've used today's 25 images. Try again tomorrow.").
- **Done for every story:** empty, loading (static skeleton for Project cold-load), error, and narrow-window states; keyboard paths; reduced motion; WCAG AA, 44×44 px targets, live regions; only `var(--…)` tokens.

## Cross-Story Dependencies

- Needs Epic 1's `user_auth`, error envelope, i18n, tokens, and `profiles` (Story 1.4 is done; 1.5 and 1.6 don't block Epic 2).

- Story 2.2 builds `generation_jobs`, the runner, the restart sweep, polling, storage, and the extraction pipeline that Stories 2.4–2.7 and Epics 3–6 reuse. Story 2.3's gate wraps 2.2's upload route.
- Story 2.4 introduces the LLM gateway and mock mode; Stories 2.5 (`extract_image_text`, plus `services/usage`) and 2.6 (`detect_topics`, saved in the same processing transaction) extend it.
- Story 2.7's tombstone uses `jobs.cancel_for_material` and `usage.release`; its "also remove its mistakes" checkbox arrives in Story 3.3.
- Later: Epic 3 adds `topics.resolve_scope` on these Topics and Sections; Epic 6 reuses the privacy gate, quota, integrity rules, and `material_processing` via `materials.create_from_batch`; Epic 7 adds archive/delete on `projects`.
